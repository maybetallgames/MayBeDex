# MayBeDex

Public, machine-readable prefab metadata catalog for the MayBeTall Games Unity project.

MayBeDex is generated from the private `LetsDive` project and is designed to make asset lookup cheap and precise: search the small text catalog first, resolve the exact Unity GUID/path, then work with the asset inside the private project.

## Why metadata-only

The current SyntyPass licence prohibits using Synty assets in datasets utilised by generative AI programs. For that reason, the public/AI-searchable MayBeDex build intentionally does **not** publish Synty preview images or image sidecars. The high-quality renders generated by `LetsDive` stay local/private for your own development workflow.

Only text metadata is copied into this repository.

## Stable Pages endpoints

Once GitHub Pages is enabled:

- `https://maybetallgames.github.io/MayBeDex/catalog.tsv` — compact lookup-first catalog
- `https://maybetallgames.github.io/MayBeDex/catalog.json` — complete machine-readable metadata
- `https://maybetallgames.github.io/MayBeDex/packs/index.json` — pack list/counts
- `https://maybetallgames.github.io/MayBeDex/packs/<pack>.tsv` — cheap per-pack lookup
- `https://maybetallgames.github.io/MayBeDex/packs/<pack>.json` — detailed per-pack metadata
- `https://maybetallgames.github.io/MayBeDex/prefabs/<unity-guid>/` — one crawlable text page per prefab
- `https://maybetallgames.github.io/MayBeDex/version.json` — generation/schema/source information

Unity GUIDs are the permanent public identifiers, so renaming or moving a prefab does not break its MayBeDex URL.

## Input schema

`catalog-source/_lookup.tsv` exactly matches the lookup generated by `LetsDive/Assets/MayBeTall/Editor/RenderAllPrefabPreviews.cs`:

```text
version guid name pack assetPath imagePath aiPreviewPath kind particles renderers skinned lods colliders boundsXYZ dependencyHash componentHints
```

The public builder deliberately ignores `imagePath` and `aiPreviewPath`.

## Update from LetsDive on Windows

From a local MayBeDex checkout:

```powershell
./tools/import_letsdive_catalog.ps1 -LetsDivePath "C:\path\to\LetsDive"
```

That copies only:

```text
PrefabPreviews/Synty/_lookup.tsv
PrefabPreviews/Synty/_catalog.json
```

into `catalog-source/`. Commit and push those two metadata files. A push to `main` runs `.github/workflows/pages.yml`, builds `_site`, and deploys GitHub Pages.

## GitHub Pages one-time setup

In this repository open **Settings → Pages → Build and deployment → Source → GitHub Actions**. After that, pushes to `main` deploy automatically.

## Local build

```bash
python tools/build_site.py
```

The generated site is written to `_site/` and is intentionally ignored by git.
