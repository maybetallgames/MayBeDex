# MayBeDex

Machine-readable prefab metadata for the MayBeTall Games Unity project.

MayBeDex has one job: make it cheap and precise to identify an existing prefab, then hook that exact prefab up inside the private `LetsDive` Unity project.

There is no website and no GitHub Pages deployment. ChatGPT can search and fetch this repository directly through the connected GitHub integration.

## What it contains

The primary file is:

```text
catalog-source/_lookup.tsv
```

Each prefab row can include:

- Unity GUID
- prefab name
- Synty pack
- Unity asset path
- rough kind (`effect`, `character`, `environment`, `weapon`, `vehicle`, `prop`)
- particle-system count
- renderer/skinned-renderer counts
- LOD-group count
- collider count
- approximate bounds
- dependency hash
- useful component hints

The optional catalog summary is:

```text
catalog-source/_catalog_info.json
```

No prefab preview images, image sidecars, meshes, textures, or other asset content are copied into MayBeDex.

## Source schema

`catalog-source/_lookup.tsv` matches the lookup generated by `LetsDive/Assets/MayBeTall/Editor/RenderAllPrefabPreviews.cs`:

```text
version guid name pack assetPath imagePath aiPreviewPath kind particles renderers skinned lods colliders boundsXYZ dependencyHash componentHints
```

`imagePath` and `aiPreviewPath` may remain as text fields in the source TSV, but MayBeDex does not copy or host the referenced images.

## Update from LetsDive on Windows

From a local MayBeDex checkout:

```powershell
./tools/import_letsdive_catalog.ps1 -LetsDivePath "C:\path\to\LetsDive"
```

That copies only:

```text
PrefabPreviews/Synty/_lookup.tsv
PrefabPreviews/Synty/_catalog_info.json
```

into `catalog-source/`. Commit and push those metadata files.

## Intended ChatGPT workflow

When asked to find a prefab, ChatGPT should search MayBeDex metadata first, narrow to exact candidates using name/pack/path/type/components, then use the private `LetsDive` repository to wire the selected prefab into the game.
